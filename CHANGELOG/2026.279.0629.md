# 2026.279.0629 — fix(schema): the marketplace version stamp is optional, not required

## Summary of changes

The org-wide cutover (*"chore(schema): drop the retired config version: stamp"*) removed the
`version:` stamp from every `marketplace:` entity, because the marketplace versions by commit SHA
— `marketplace/README.md` states it plainly:

> *"No `version` fields anywhere: plugins version by the marketplace commit SHA, so every corpus
> update is picked up on `/plugin marketplace update`."*

**That cutover never updated this schema.** `#MarketplaceInput.version` stayed **required**, so the
one repo carrying a `marketplace:` entity fails `charly box validate` — the gate the host
validates that entity against through this plugin:

```
node "marketplace": plugin kind:marketplace: plugin_input fails
#MarketplaceInput: #MarketplaceInput.version: incomplete value =~"^[0-9]+[.][0-9]+[.][0-9]+$"
```

This makes it optional — matching `#MarketplaceFamilyInput.version?`, which this same file
**already** treats as optional. A legacy config that still carries a stamp keeps loading; the
emitted manifests already omit it via `omitempty`, so commit-SHA versioning holds.

**Two files (two commits):**

- `candy/plugin-harness-kind/schema/marketplace.cue` — `version` → `version?` on
  `#MarketplaceInput`, with the reason recorded in-place so a future reader does not re-require
  it. This schema is hand-written and embedded (`//go:embed schema/*.cue`), so there is no
  generated artifact to regenerate.
- `candy/plugin-harness-kind/marketplace_input_test.go` — **new coverage** that FAILS on the
  pre-change schema: a version-less body must validate (the new behaviour), a legacy body
  carrying a CalVer must still validate (back-compat), and a malformed version must still be
  rejected. It compiles the SAME served schema the load gate compiles, through the SDK's own
  validator (`sdk.NewSchemaValidator(schemaFS, "schema")`).

**Closes / relates to:** unblocks opencharly/marketplace#422. Sibling leg: opencharly/spec#200
(the core `#Marketplace`). The entity-side restore this replaces is reverted in
opencharly/pod-charly-hooks.

**Breaking change + rollback:** none — a required field becomes optional, so every config that
validated before still validates. Rollback is a revert.
