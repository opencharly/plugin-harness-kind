# 2026.288.1214 — feat(schema): the skill node's body may live in .agents/skills

## Summary

**Leg L3** of the `.agents/skills` relocation (`opencharly/opencharly#496`): the `skill` kind's **served schema** accepts the file-sourced shape.

`candy/plugin-harness-kind/schema/skill.cue` holds the self-contained `#SkillInput` that the **load gate** validates every authored `skill:` node against (`validateAuthoredPluginInput`), and it is a faithful reproduction of the core `#Skill`. The relocation moves a skill's body out of its entity into `<tree>/<name>/SKILL.md` (+ `references/<stem>.md`), leaving the node to carry the routing the consumers read — so `name`, `description` and `content` become **optional** here in step, or every repository that moves a body would fail its own `charly box validate` with `#SkillInput.content: incomplete value`.

The set this commit actually declares, read off the commit rather than restated from intent:

```
$ git show HEAD:candy/plugin-harness-kind/schema/skill.cue | sed -n '/#SkillInput: close({/,/^})/p' | grep -oE '^\s+[a-z_]+\??:' | tr -d ' \t' | tr '\n' ' '
name?: family: owner: description?: content?: type?: model?: tools?: references?: triggers?: category?:
# required = the two entries with no `?`: family, owner
```

So the relaxation is exactly three keys. `family`, `owner`, the skill-id pattern, the `!=""` refinements and the `category`/`type` defaults are untouched — and (c)/(d)/(e) below prove they still bite.

**The in-line form stays accepted.** The entities that still carry their body in-line keep validating; this leg only widens the door. The narrowing — dropping `content:` from the core schema and from this one — belongs to the relocation's final leg, so nothing that works today stops working when this lands.

Also in the diff: the new `skill_input_test.go`, and the candy `description:` correction (it still claimed a `skill:` node carries the "FULL inline skill definition (metadata + markdown content)", which this change makes false).
