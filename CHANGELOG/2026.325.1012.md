# 2026.325.1012 — feat(skill): kind:skill serves owned content — the composed skills' install and label, and the project's skill diagnostics

## Summary

`kind:skill` serves **owned content** (`ops.OpContent`), the plugin half of opencharly/sdk#598. DESIGN gives the `skill` kind to the documentation plugin, and D-PLUG-1 says a plugin owns its words end to end, so the skill rules now live here, beside the kind's decode:

- **Box scope** (a build). The kind installs the skills whose owner the box composes: each file of the derived body (`.agents/skills/<name>/SKILL.md` + `references/<stem>.md`, or an agent's `.agents/agents/<name>.md`), at the path a harness in the image reads it from. The **same walk** produces the `ai.opencharly.skill` label (routing metadata from the node, prose from the file), so the install and the label always agree.
- **Project scope** (`charly box validate`). Every node is diagnosed whether or not a box composes it:
  - an image owner, the sdk#434 ruling, verbatim;
  - an owner that is no candy of the project;
  - a body that does not exist at the owner's repo root (opencharly/opencharly#530);
  - a file that disagrees with its node.
- A body is derived from its node's name and never authored in the node (DESIGN), so an in-line-only node is diagnosed rather than labelled.
- `skill` declares `contents` in its capability, which is how the host lists it in `content_kinds`.

These rules and their tests move here from sdk's deleted label collector (opencharly/sdk#607 maps every deleted test to its replacement) and from plugin-box's `validate_skills.go`. The candy description is corrected: the label no longer comes from a collector, and the in-line form is no longer accepted.
